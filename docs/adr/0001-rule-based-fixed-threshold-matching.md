# Rule-based matching with fixed thresholds, no learning, no cross-user cache

Track matching (#7) uses a deterministic weighted score (title 0.4, artist 0.3, duration 0.2, album 0.1) with fixed thresholds (0.85 auto-accept, 0.55 review floor), plus an ISRC-verified path that bypasses the score entirely. We considered letting the threshold adapt from the user's review decisions, but Spotify Developer Policy III bans ingesting Spotify content into a machine learning or AI model, and an adapting threshold trained on Spotify track metadata plus the user's accept/reject history sits too close to that line. We also considered a per-transfer configurable threshold, rejected as a UI surface with no users to justify it at 5-person scale. Both are easy to add later; the score weights themselves are a starting guess, meant to be hand-tuned once real transfers produce data, not to be learned automatically.

A related, separately reversible call: no cross-user match caching in v1. At 5 allowlisted users the savings are negligible, and a shared cache would couple otherwise-isolated users' jobs together for a privacy cost (a cached match reveals what track another user had) that isn't worth paying yet. Revisit as a per-job-only cache if write-quota pressure makes re-matching expensive.
